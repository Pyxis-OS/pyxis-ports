OpenArena 0.8.8 corresponding-source downloads

The preferred asset forms and release game-module C sources accompany the game
as separate public downloads, not as installed game files. From the repository
where you obtained this package, use:

  sources/openarena/0.8.8/README.txt
  sources/openarena/0.8.8/SHA256SUMS

The individual source filenames and SHA-256 pins are also installed beside
this notice in source-downloads.sha256. Internal build-cache URLs are not the
public source location.

The eight Debian data .orig archives preserve upstream asset exports and the
available editable maps, models, images and music source. Their .dsc and Debian
tars retain copyright/provenance, selected-source inventories and build rules.
The source snapshots are r901 (0.8.1 assets), r931 (0.8.5 patch) and r947 (0.8.8
patch). They are a manually assembled upstream export, not a guaranteed
bit-reproducible asset pipeline. Music source includes the artist's supplied
WAV samples and process notes, without claiming an additional DAW project.

Game-source versions 0.8.1, 0.8.5 and 0.8.8 supply the QVMs retained in
pak0.pk3, pak6-patch085.pk3 and pak6-patch088.pk3 respectively. The following
steps were host-built for all nine modules; the installed bytecode is unchanged.

QVM BUILDING

1. Unpack the three game orig archives. Unpack the 0.8.1 Debian tar separately.
   In the 0.8.1 orig root apply only its game import:
     patch --batch -p1 -i <debian>/patches/0001-Import-game-logic-from-openarena-modSDK-0.8.1.patch
   Do not apply the later Debian gameplay or engine patches.
2. From the 0.8.5 game root copy code/cgame/cg_syscalls.asm,
   code/game/g_syscalls.asm and code/ui/ui_syscalls.asm into the same 0.8.1
   paths. These cover the actually referenced 0.8.1 syscalls. Restore
   code/game/bg_lib.c to the 0.8.1 cgame/UI QVM build lists (the native-module
   import removed it); qagame already includes it. Use -DSTANDALONE for 0.8.1.
3. In the 0.8.5 game root apply this download's
   openarena-0.8.5-qagame-runtime.patch with patch -p1. This reconstruction
   removes one extra SetTeam return in the supplied source to match the
   release bytecode's fall-through; it is not an authentic upstream patch.
4. Build external host q3lcc/q3cpp/q3rcc, lburg and q3asm from pinned ioquake3
   87a99d18206e878a20289f05ac3c16005dcae5c3 at
   https://github.com/ioquake/ioq3 (cmake/tools/CMakeLists.txt).
   Put q3lcc/q3cpp/q3rcc together. These are compiler tools, not the Pyxis client.
5. For each version compile the ordered Q3CGOBJ_, Q3GOBJ_ and Q3UIOBJ_ C lists
   in its Makefile, mapping bg_* to code/game, classic UI to code/q3_ui and
   shared files to code/qcommon. Add bg_lib.c if absent. Invoke:
     q3lcc -D<CGAME|QAGAME|UI> -o <output.asm> <input.c>
   Omit the module define for code/qcommon files. Add -DSTANDALONE for 0.8.1.
   q3lcc defines Q3_VM itself. Link in list order, vmMain first:
     q3asm -o <module.qvm> <ordered assembly files> <module_syscalls.asm>
   Omit -vq3: the shipped modules use VM_MAGIC_VER2.

The 0.8.5/0.8.8 cgame/UI modules rebuild byte-identically. After the one-line
0.8.5 reconstruction, its qagame differs only by __DATE__, as does 0.8.8
qagame. For an exact 0.8.5 rebuild, set TZ=UTC and
SOURCE_DATE_EPOCH=1262476800 before compiling. Original dates are Jan  3 2010
and Jan 28 2012 respectively. The
0.8.1 outputs retain two extra unused shared helpers from its supplied engine
source (Q_isanumber/Q_isintegral); full bit identity is not claimed there.
No regenerated QVM is substituted into the game package.

The compiler has its own licences: q3asm is GPL-2.0-or-later; lcc has custom
restricted terms in code/tools/lcc/COPYRIGHT. It is a separately obtained
compiler prerequisite, not included in the game or relabelled GPL. The
QVM bg_lib.c notice is BSD-3-Clause and is retained with the game notices.

The engine's native-client source, covered SDL backend source and their notices
retain the ordinary bundle layout. No retail Quake 3/Team Arena data is present.
